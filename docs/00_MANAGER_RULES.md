# ADBMedic — регламент управления проектом

## Текущая цель: диагностический архив для доверенного ИИ

Пользователь разрешил сохранять в локальном ZIP жалобу, модель/Android, реальные пакеты, UID/PID, периоды и подробные диагностические данные. ИИ должен объяснять причины энергопотребления, типы и количество событий, давать план действий и назначать точечные read-only ADB-команды для продолжения исследования. Контракт включён в AI-ANALYST.md. Правила публикации исходников и запрет на попадание диагностики в GitHub сохраняются. Автоматическая отправка и выполнение рекомендаций запрещены; известные секреты блокируют упаковку. Это решение заменяет прежнее требование обезличенных P-меток и запрет подробных дампов в пользовательском архиве.

## Новое разрешение: CI/CD

Владелец разрешил GitHub Actions для синтетических проверок в Windows PowerShell 5.1/7, аудита исходников/index/истории и публикации проверенного архива исходников как Actions artifact. Разрешён только `.github/workflows/ci.yml`; Actions закреплены точными проверенными SHA и имеют read-only доступ. Публикация релизов, секретов и диагностики не разрешена. После успешного первого запуска main защищается обязательной проверкой CI и запретом force push/удаления. Последующие изменения — через PR с успешными проверками.

## Новое разрешение: безопасный ручной ZIP

Владелец явно разрешил этап безопасной передачи отчёта: меню без автоматического открытия браузера, проверенный ZIP производных измерений и инструкция для нейросети с подробными рекомендациями пользователю. Сырые файлы, реальные имена процессов/UID/PID, модель, серийники, время по часам и исходная жалоба остаются локальными. Передавать ZIP в чат пользователь должен вручную. Автоматический облачный анализ и экспорт сырых дампов по-прежнему запрещены. Это разрешённое продолжение после TASK-001; проверка перед Git-публикацией сохраняется.

## Обязательная защита

1. Перед каждым push повторно проверить рабочее дерево, index, все отправляемые коммиты и их метаданные. При потенциальных личных данных остановить публикацию и сообщить категорию без значения. Не отключать проверки ради публикации.
2. Не публиковать реальные имена пользователей, домашние пути, приватные контакты, аппаратные идентификаторы, отпечатки устройств, материалы прежних расследований, сырые отчёты/логи, пароли, сертификаты и любые приватные/подписные ключи. Не искать их за пределами проекта.
3. Публичная почта выше, публичное имя автора и необходимые URL выбранного репозитория — узкие исключения. Они не разрешают прочую персональную информацию.
4. `.gitignore` — дополнительная защита. Главные проверки — положительный список исходников и независимый аудит фактических Git-объектов. Подключить локальные pre-commit, commit-msg и pre-push hooks. Они не заменяют аудит и не являются серверной защитой.
5. Проверки только офлайн, на синтетических данных, без телефона, реального ADB, загрузки Platform-Tools или обращения к другим проектам. Сетевые исключения: разрешённая работа с исходным репозиторием и реализованный установщик исходников с согласием.
6. Сырые диагностические данные остаются локальными. ZIP диагностики и облачный анализ заблокированы до отдельной приёмки TASK-002. Не считать хеширование идентификаторов анонимизацией.
7. Локальная диагностика только read-only и с согласием. Запрещены root, reboot, kill, изменение пакетов/настроек и прошивка.
8. Исходный архив формировать только по положительному списку после аудита; повторно распаковать и проверить. Не включать Git-историю, приватные каталоги, CI, бинарные файлы или диагностику.
